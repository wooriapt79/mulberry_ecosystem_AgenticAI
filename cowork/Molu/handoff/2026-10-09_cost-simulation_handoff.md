## 1. 목표

"주민 한 번 응대에 드는 비용"을 대형 모델만 쓸 때와 Mulberry 구성(Decider · Edge · 인제 토크나이저)으로 나눠 % 절감으로 보여 주고, 이를 **계속 낮춰 갈 목표선과 최적화 주기**로 만든다.

## 2. 결과 (가정 기반 추정 · 실측 아님)

몬테카를로 2만 회, 1달러 = 1,400원.

| 구성 | 1회 응대 비용 (중앙값) | 대형 모델만 대비 절감 | 대형 모델 호출 |
|---|---|---|---|
| A. 대형 모델만 | 약 26원 | 기준 | 약 4회 |
| B. + Mulberry Decider | 약 6.4원 | **76%** (62~84%), 2만 회 모두 절감 | 약 1.7회 |
| C. + Edge | 약 9.9원 | **63%** (14~80%) | 약 1.2회 |
| D. + 인제 토크나이저 | C와 같음 | 외부 API 요금 변화 없음 | — |

- Edge는 **기기 1대가 하루 약 54회 이상** 응대해야 B보다 싸진다. 한 가구용 Edge의 가치는 비용이 아니라 오프라인 동작·개인정보·응답 속도다. 가게·마을회관 허브에서는 비용도 줄인다.
- 인제 토크나이저는 외부 대형 모델 요금을 줄이지 못한다. 우리 모델(Decider·Edge)의 속도를 높인다.
- 결과를 가장 크게 흔드는 가정: 기기당 하루 응대 수(-14%~74%) > 대형 모델 입력 단가(42%~71%) > 턴당 호출 수.

## 3. 결정 사항

1. 시뮬레이션 수치는 외부에 **"시뮬레이션 추정"** 으로만 쓴다. 실측으로 통과한 단계만 "달성"이라고 쓴다.
2. 목표는 정해 두고 **계속 내린다** (re.eul: "최적의 집적화를 계속해야 한다").

| 단계 | 1회 응대 비용 | 절감률 | 통과 조건 |
|---|---|---|---|
| S0 기준선 증명 | 약 6.4원 | 76% | 실측으로 75% 이상, 최악 쪽(P10) 60% 이상 |
| S1 1차 최적화 | 4.8원 이하 | 82% | 대형 모델 호출 1.4회 이하 |
| S2 2차 최적화 (Edge 허브, 하루 100회) | 4.3원 이하 | 83% | 가게·마을회관 설치 |

3. **안전을 토큰과 바꾸지 않는다.** 한 주기의 절감은 대화 정책 시험 7/7(승인 게이트·거절·오프라인) 통과 시에만 인정한다.
4. 최적화 주기: 측정 → 가장 큰 원인(민감도) → 레버 하나 개선 → 품질 게이트 → 비용 장부 기록·목표 갱신.

## 4. 레버 (S1·S2 목표는 이 값이 달성될 때의 추정)

| 레버 | 지금 (가정) | 목표 |
|---|---|---|
| Decider → 대형 모델 넘김 | 10~30% | 15% 이하 |
| 자유 생성이 필요한 턴 | 30~70% | 40% 이하 |
| 대형 모델 호출당 입력 토큰 | 800~1,800 | 1,000 이하 |
| Edge가 처리하는 생성 | 30~70% | 50% 이상 |
| 우리 모델 토큰 감소 (인제 토크나이저) | 0~30% | 15% 이상 |
| Edge 설치 장소 | 하루 5~50회 | 54회 이상 장소 우선 |

## 5. 코드 (mulberry-synthetic-lab, 레포 생성 전)

- `mslab/costsim.py`: 시뮬레이션, 민감도, 손익분기, 목표 점검, 비용 장부
- `mslab/data/cost_assumptions.yaml`: 가정 범위 (값만 바꾸면 재계산)
- `mslab/data/cost_targets.yaml`: 단계·통과 조건·레버 (목표를 내릴 때 이 파일만 수정)
- 실행: `python -m mslab.cli cost --label "주기 이름" --source assumption|measured`
- 결과: `lab_output/cost_targets.md`, `lab_output/cost_ledger.jsonl`
- 테스트 11개 통과 (비용 목표·장부 테스트 포함)
- 첫 기록 C0 (가정 v0.1): S0 추정상 달성(실측 필요), S1·S2 미달
