# KeBin Issue Trigger

GitHub Issue를 KeBin의 비동기 작업 접수함으로 사용하는 워크플로입니다.

## 사용 방법

일반 Issue 본문 또는 댓글에 정확한 태그 `#KeBin`을 포함합니다.

예시:

```text
#KeBin
Issue #15의 Phase A 첫 작업 묶음을 확인하고 착수 브리핑을 남겨주세요.
```

워크플로가 감지하면 다음을 수행합니다.

1. `kebin-task` 라벨을 생성하거나 재사용합니다.
2. 대상 Issue에 라벨을 부착합니다.
3. 요청자, 접수 시각, 원문 링크를 포함한 접수 댓글을 남깁니다.
4. 같은 이벤트가 다시 처리되면 중복 댓글을 만들지 않습니다.

## 안전 경계

- 일반 Issue만 처리하며 Pull Request 댓글은 제외합니다.
- 봇이 작성한 댓글은 트리거하지 않습니다.
- 저장소 콘텐츠는 읽기만 허용합니다.
- Issue 라벨과 접수 댓글 작성 권한만 사용합니다.
- 코드 수정, 브랜치 생성, 배포, 결제, 외부 메시지는 실행하지 않습니다.
- 실제 작업은 별도 브랜치, Draft PR, Human 승인 절차를 따릅니다.

## 수동 검증

Actions 화면에서 `KeBin Issue Trigger`를 선택하고 `workflow_dispatch`로 Issue 번호를 입력할 수 있습니다. 수동 검증은 Issue 접근 가능 여부만 확인하며 댓글이나 라벨을 변경하지 않습니다.

## 트리거 범위

- Issue 신규 생성
- Issue 본문 수정
- Issue 재개
- Issue 댓글 신규 작성

태그는 오작동을 줄이기 위해 대소문자를 구분한 정확한 `#KeBin` 문자열을 사용합니다.
